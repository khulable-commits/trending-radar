# Evaluation goal

Evaluate how worth a reader's attention a trending repository or model is, given that it is already on a public trending ranking.

# Scoring rubric

- **9-10: Must see.** A fast-spreading project that changes how a common task is done, or a model release that many teams will evaluate now.
- **7-8: High value.** A project or model with a clear, concrete use and a strong momentum signal (large star, like, or download gain) in a widely used area.
- **5-6: Worth a glance.** Useful for a specific stack or niche, or momentum driven by novelty alone.
- **3-4: Low priority.** Duplicative of an established project, thin documentation, a wrapper with little substance, or a demo that does not ship anything usable.
- **0-2: Noise.** Unmaintained, misleading, purely promotional, or unsafe to run.

# Evaluation guidance

The ranking itself is evidence of attention, not of quality. Prefer items where the content or metadata explains what the project or model actually does: a concrete capability, a measurable result, a supported task, a license, or an integration. Do not infer maturity from star counts alone. Penalize a description that is only marketing language. When the item is a Hugging Face model, weigh the task tag and reported downloads; when it is a repository, weigh the primary language and what the description promises against the tags or topics shown.

Use three to five specific topic tags.
